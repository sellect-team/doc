01. 전체 구조

설계 원칙 다섯 가지

모든 세부 설계는 아래 다섯 원칙을 따르며, 원칙과 충돌하는 요구는 협의 항목으로 승격합니다.

원칙 1

격리를 데이터 계층에서

골프장 격리는 화면이나 API 코드가 아니라 DB 행 수준 보안(RLS)에서 보장합니다. 코드 실수가 격리 사고로 이어지지 않게 합니다.

원칙 2

수집과 조회의 분리

단말 수집 경로와 화면 조회 경로를 프로세스 단위로 분리해, 조회 부하가 수집 유실로 이어지지 않게 합니다.

원칙 3

원본 보존 · 판정 재계산

수신 원본(CAN 프레임 · 위치)은 그대로 적재하고, 상태 · 트립 · 알림은 원본에서 재계산 가능하게 설계합니다.

원칙 4

이력은 지우지 않는다

차량 · 골프장 · 계정의 삭제는 비활성화로 처리하고, 정비 기록 수정은 이전 값을 이력으로 보존합니다. 감사 로그는 전 쓰기 작업에 적용합니다.

원칙 5

협의 값은 설정으로

수집 주기 · 속도 임계 · 보관 기간 등 협의 대상 값은 파라미터 테이블과 환경 변수로 두고, 확정 시 배포 없이 반영합니다.

원칙과 충돌하는 요구는 착수 협의 안건으로 등록SAILINGSTONE · 3

인증

단말 토큰 + TLS

연결 수립 시 단말 토큰을 검증하고, 이후 패킷은 세션에 귀속합니다. 토큰은 등록 화면(SCR-080)에서 발급 · 회수합니다.

재전송

확정 문서 반영 절차 - 실제 단말 프로토콜 문서를 받으면 수신 어댑터(파서 1개 파일)만 교체합니다. 어댑터 출력은 내부 표준 메시지(NormalizedPacket)로 고정되어 이후 파이프라인은 수정이 없습니다. (TBD - 단말 인터페이스 문서 · 전송 주기)

에러 코드는 대역으로 원인 계층을 구분해, 로그 검색과 화면 안내문 매핑을 단순하게 만듭니다.

대역계층
ERR-1xxx인증 · 세션
ERR-2xxx권한 · 테넌트
ERR-3xxx요청 검증
ERR-4xxx자원 · 상태 충돌
ERR-5xxx수집 · 단말
ERR-9xxx서버 내부
코드의미화면 처리
ERR-1001 · 1002비밀번호 불일치 · OTP 불일치남은 시도 횟수 안내
ERR-1003토큰 만료무중단 갱신 시도 후 로그인 화면
ERR-2001 · 2002기능 권한 없음 · 타 골프장 접근접근 불가 안내(메뉴 숨김이 1차 방어)
ERR-3001 ~ 3003필수 누락 · 형식 오류 · 중복 값필드 단위 오류 표시(3003은 기존 자원 링크)
ERR-4001 · 4002자원 없음 · 상태 충돌4002 예 - 열린 트립 재계산, 본인 권한 하향
ERR-5001 · 5002단말 인증 실패 · 시퀀스 이상화면 미노출, 수집 지표로 집계
ERR-9001내부 오류trace_id 표시 + 재시도 안내
안내문은 코드 - 문구 사전으로 관리합니다 - 화면은 코드로만 분기하고 문구는 사전 파일에서 읽어, 문구 수정이 배포 없이 가능합니다.
코드 신설은 이 대역 규칙 안에서만 허용SAILINGSTONE · 30

가용성

프로세스 자동 재시작

컨테이너 헬스체크와 자동 재시작을 기본으로 하고, 수집 유실은 단말 재전송이 흡수합니다.

백업

일일 스냅숏 + WAL

DB는 일일 스냅숏과 WAL 아카이브로 시점 복구를 지원하고, 복구 절차를 운영 문서로 제공합니다.

관측

지표 · 로그 · 추적

단계별 처리 시간 · 폐기 카운트 · 큐 적체를 지표로 수집하고, trace_id로 요청 - 로그를 연결합니다.
