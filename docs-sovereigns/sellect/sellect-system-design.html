늦은 응답의 오염 차단

로그인 시도 전에 세대를 +1(beginSessionReplacement)하고, 모든 요청 · 응답 · 저장이 세대를 재검증합니다. 이전 계정의 늦은 응답은 CanceledError로 버려져 새 계정 캐시를 오염시키지 못합니다.

401 복구

single-flight 갱신

같은 세대의 동시 401은 refresh 요청 하나를 공유(회전 상호 무효화 방지)하고, 실패 시 expireSession - 캐시 clear + 로그인 화면입니다.

저장소

웹 localStorage · 네이티브 SecureStore

저장 · 삭제는 직렬화 큐로 순서를 보장하고(삭제는 refresh 먼저), 한쪽 토큰만 남으면 복원 시 전체 폐기합니다.

04. 핵심 설계

SSE 파이프라인과 경합 방지

Authorization 헤더 때문에 EventSource 대신 fetch 스트림 SSE를 쓰며, 다중 인스턴스까지 설계되어 있습니다.

구간설계
서버 발행ChatRealtimeFanout - Redis Pub/Sub(sellect:{env}:chat-realtime:v1, HMAC 서명, 자기 echo 무시)로 다중 인스턴스 전파
연결 등록ChatSseService - 등록 직전 권한 TOCTOU 재검사, 차단 시 SSE 철회(chat.room.revoked)
프론트 파서WHATWG 준수 자체 파서 - 청크 경계 · CRLF · BOM 처리, EOF 미완 이벤트 폐기
재연결지수 백오프 최대 30초 + equal jitter, 15초 건강 연결은 attempt 리셋, 401은 1회 갱신 후 재시도
폴백chatRooms · unread 90초 폴링(SSE 단절 대비) · 알림 30초
경합 방지 3중

REST와 SSE의 합류점

① 캐시 쓰기 시점에 mergeRoomSnapshot(structuralSharing)으로 병합 ② afterMessageId 커서는 완전한 REST 스냅샷으로만 전진 ③ 롤백된 낙관적 메시지는 discarded 목록으로 부활 차단.

낙관적 전송
