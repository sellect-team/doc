교실의 AI, 이미 시작된 변화

01 · Why Now

학생들은 이미 AI를 쓰고 있습니다. 질문은 "쓰게 할 것인가"가 아니라 "어떤 울타리 안에서 제대로 배우게 할 것인가"입니다.

POLICY정책 환경

지침은 나왔고, 도구가 없다

교육부·교육청이 수행평가 AI 활용 관리 방안을 확정하고 2026학년도 지침을 개정했습니다. AI 디지털교과서와 함께 "올바른 활용"이 공식 과제가 됐지만, 정작 학교 현장에는 통제 가능한 실습 환경이 없습니다.

규칙만 있고 놀이터가 없는 상태 - 지금이 도입 적기입니다.
CLASSROOM교실 현실

개인 계정으로 각자 접속

학생들은 집에서 개인 계정으로 챗봇을 씁니다. 선생님은 누가 무엇을 물었는지, 과제를 AI가 대신 했는지 알 수 없습니다. 나이 제한·개인정보·유해 답변 문제도 전부 개인에게 맡겨져 있습니다.

보이지 않는 사용을 보이는 교실 활동으로 옮겨야 합니다.

선생님의 세 가지 고민에서 출발합니다

01 · Why Now

AI 수업을 해 본 선생님들의 고민은 놀랍도록 비슷합니다. 이 플랫폼의 모든 기능은 아래 세 문제의 해답으로 설계됐습니다.

고민 01

"계정과 비용을 어떻게 하나요?"

학생 수만큼 유료 계정을 만들 수도, 교사 계정 하나를 돌려 쓸 수도 없습니다. 학생마다 쓰는 양이 달라 비용 예측도 안 됩니다.

"AI 수업을 하고 싶어도 30명 계정 문제에서 막힙니다."
→ 학교가 API 키 하나만 등록하면, 반별·학생별로 사용량을 나눠 줍니다.
고민 02

"아이들에게 안전한가요?"

유해 답변, 개인정보 입력, 나이 제한, 그리고 AI가 과제를 대신 해 주는 문제까지 - 일반 챗봇을 그대로 열어 줄 수는 없습니다.

"뭘 묻고 뭘 답했는지 보이지 않는 게 제일 불안해요."
→ 모든 대화가 기록되고, 위험 신호는 즉시 선생님께 알립니다.
고민 03

"만든 것을 어디에 모으나요?"

학생들이 AI로 만든 글·그림·웹 작품이 개인 화면에서 사라집니다. 모아서 전시하고, 서로 배우고, 평가에 쓸 방법이 없습니다.

"잘 만든 작품인데 수업이 끝나면 그냥 없어져요."
→ 승인을 거쳐 갤러리에 올리고, 친구들이 보고 배우게 합니다.
계정·비용, 안전, 산출물 - 세 고민을 하나의 플랫폼으로 풉니다. 이름하여 AI 놀이터입니다.

AI 놀이터 - 한 장으로 보는 콘셉트

02 · Concept

선생님이 울타리를 치고, 학생이 그 안에서 마음껏 만들고, 만든 것이 학급의 자산으로 쌓이는 만들기 - 올리기 - 배우기 순환 구조입니다.

① 수업방 열기

선생님이 주제·AI 페르소나·사용 한도를 정해 수업방을 만들고, 학생은 코드로 입장합니다. 학생 개인 계정이 필요 없습니다.

›
② 만들기

안전 필터가 켜진 AI와 대화하며 글·그림·퀴즈·웹 작품을 만듭니다. 어려우면 힌트만 주는 학습 모드로 스스로 풀게 합니다.

›
③ 올리기

완성작을 제출하면 선생님 승인을 거쳐 학급 갤러리에 게시됩니다. 웹 작품은 자동으로 주소가 발급돼 바로 열어 볼 수 있습니다.

›
④ 함께 배우기

친구 작품에 칭찬과 질문을 남기고, 잘된 프롬프트를 따라 해 봅니다. 선생님은 과정 기록으로 평가하고 다음 수업을 설계합니다.

학생에게는 PLAYGROUND

혼내지 않는 연습장입니다. 실패해도 되는 공간에서 AI에게 말 거는 법, 결과를 의심하는 법, 내 생각을 얹는 법을 배웁니다.

선생님에게는 CONTROL TOWER

수업 설계 도구이자 관제탑입니다. 한 화면에서 반 전체의 활동을 보고, 사용량을 조절하고, 도움이 필요한 학생을 먼저 찾아냅니다.

학교·교육청에는 GOVERNANCE

어떤 AI를 얼마나 썼는지, 예산이 어디에 쓰였는지 집계됩니다. 지침 준수가 문서가 아니라 시스템으로 보장됩니다.

학부모에게는 TRUST

아이가 학교 관리 아래에서 AI를 배운다는 신뢰입니다. 대화는 기록되고, 데이터는 학습에 쓰이지 않으며, 유해물은 차단됩니다.

기능 ② AI 등록·배분 - 키 하나로 반 전체가 씁니다

03 · Features

학교(또는 교육청)가 상용 AI의 API 키를 등록하면, 플랫폼이 학급→학생 단위로 사용량을 쪼개서 나눠 주고 실시간으로 집계합니다.

키 등록 BYOK

Claude·GPT·Gemini 등 교육청이 계약한 AI의 키를 등록합니다. 키는 암호화 보관되고 학생에게 절대 노출되지 않습니다. 모델별로 용도를 지정합니다 - 기본 대화는 경량 모델, 심화 활동만 상위 모델로.

예산 배분 QUOTA

인프라 - NHN 클라우드 공공존 위에 짓습니다

04 · Plan

학생 데이터를 다루는 시스템은 인프라부터 공공 기준이어야 합니다. CSAP 인증 국내 클라우드(NHN Cloud) 공공 전용존을 표준 인프라로 제안합니다.

교육청 도입 요건에 맞는 선택

NHN 클라우드는 CSAP 인증을 IaaS·PaaS·DaaS 전 영역에서 보유한 국내 클라우드로, 공공기관 전용 독립존을 운영합니다. 디지털서비스몰(디지털서비스 이용지원시스템)에 등록돼 있어 교육청이 카탈로그 계약으로 신속하게 조달할 수 있습니다.

학생 데이터는 국내에, 흔적은 남게

대화 기록·작품·개인정보가 모두 국내 리전에 상주합니다. 개인정보보호법과 교육청 보안 심사 기준에 맞춰 암호화 저장·접근 통제·감사 로그를 구성하고, 서비스 앞단은 클라우드 보안 서비스(WAF·DDoS 방어)로 이중 보호합니다.

학사 일정을 아는 탄력 운영

학교 트래픽은 수업 시간에 몰리고 방학에는 줄어듭니다. 컨테이너 기반(NKS) 오토스케일로 수업 시간대에는 늘리고 방학에는 줄여 운영비를 아낍니다. 학생 작품 호스팅도 같은 클러스터 안에서 격리해 운영합니다.

배치 구성 · NHN Cloud 공공존국내 리전
NKS (쿠버네티스)플랫폼 서비스 + 학생 작품 격리 호스팅 · 오토스케일 1단계
Object Storage + RDS작품 · 포트폴리오 · 대화 기록 (암호화 저장) 1단계
Security (WAF · Anti-DDoS)학생 서비스 앞단 보호 · 접근 통제 1단계
Notification (문자 · 푸시)법정대리인 동의 · 위기 알림 발송 2단계
외부 AI API 호출은 게이트웨이를 통해서만 나가고, 개인정보는 마스킹 후 전송됩니다

서비스 매핑. 이미 컨테이너로 운영 중인 플랫폼과 배포 엔진을 NHN 클라우드 공공존에 그대로 올리는 구성이라 이전 리스크가 낮습니다.

결론: 조달 가능(디지털서비스몰) + 심사 대응(CSAP 공공존) + 운영 효율(탄력 확장) - 세 조건을 한 번에 충족합니다.
