배경과 오늘의 질문

01 · Why

지난 미팅에서 확인된 질문에서 출발합니다 - "개발 부담 감소와 셀프서비스 외에, aisight의 가치는 무엇인가."

배경 01REQUEST

"태블로를 웹으로"

GBC 내부에서 태블로 대시보드를 웹 대시보드로 전환하자는 요청이 나왔습니다. 라이선스 부담, 화면 자유도, 포탈과의 이질감이 배경입니다.

배경 신호

라이선스 갱신 부담 · 화면 개선 요구 누적 · 포탈과 이원화된 사용 경험

전환 자체는 이미 결정의 방향입니다.
배경 02OPTIONS

두 갈래 견적

단순 웹 재개발과 aisight 플랫폼 - 두 견적이 이미 전달되어 있습니다. 이 문서는 그 갈림길에서 무엇이 다른지를 보이는 판단 자료입니다.

기전달

단순 웹 개발 견적 · aisight 플랫폼 견적 (별도 문서)

가격표가 아니라 구조의 차이를 봅니다.
배경 03QUESTION

오늘의 질문

소개 미팅에서 두 가지 가치는 이미 확인해 주셨습니다 - 개발 부담 감소, 지역별 담당자의 셀프 대시보드. 요청은 "그 외의 가치"였습니다.

확인된 가치 2가지

세일링스톤 개발 부담 감소 · 지역별 담당자 셀프 대시보드

이 문서 전체가 그 질문에 대한 답입니다.
이미 인정하신 2가지는 반복하지 않습니다 - 그 위에 있는 6가지를 보여 드립니다.
- 2 -SAILINGSTONE

결론 - 웹 전환은 목적지가 아니라 출발점입니다

01 · Why

단순 웹 전환은 지금의 화면을 다시 만드는 일이고, aisight 전환은 앞으로의 요구를 흡수하는 구조를 만드는 일입니다.

가치 01

요청 대기의 소멸

새 대시보드와 수정이 개발 발주 없이 담당자 손에서 당일 처리됩니다. 본사 개발 큐에 줄이 생기지 않습니다.

개발 발주 대기 0건.
가치 02

묻는 대시보드

자연어로 질문하면 차트와 요약으로 답합니다. 보는 도구가 답을 얻는 도구가 됩니다. 쓰던 개인 Claude로 이어가는 MCP 연동까지.

태블로에도 없는 층.
가치 03

지표 거버넌스

셀프서비스가 만들 지표 난립을 표준 지표 사전·권한·이력으로 통제합니다. 자유와 통제를 동시에.

같은 이름 = 같은 숫자.
가치 04

비용 구조의 전환

좌석 라이선스·건당 개발비의 "쓸수록 늘어나는 구조"가 플랫폼 단일 구조로 바뀝니다.

한계비용 최소의 구조.
가치 05

포탈은 그대로

기존 커스텀 포탈에 임베드되어 사용자 동선이 바뀌지 않습니다. 전환 프로젝트 최대 리스크의 제거.

재교육 · 이탈 리스크 0.
가치 06

확장 로드맵

리포트 자동화·문서 지능·지식그래프로 이어지는 다음 단계가 같은 플랫폼 위에 준비되어 있습니다.

별도 시스템이 아닌 모듈 추가.
이 여섯 가지가 단순 웹 개발 견적에는 없는 항목입니다 - 다음 장부터 하나씩 증명합니다.

01 · Why

가치 ① 셀프서비스 - 요청 대기가 사라집니다

02 · Value

"지역별 담당자가 원하는 대시보드"라는 니즈의 본질은 화면이 아니라 기다리지 않는 것입니다.

지금의 경로 AS-IS

현업 요청 → 본사 취합 → 개발 큐 → 개발·검수 → 배포. 잘 돌아가도 주 단위, 요청이 몰리면 월 단위입니다. 그 사이 업무는 엑셀로 돌아갑니다.

도입 후 경로 TO-BE

담당자가 위젯을 골라 조합하고 저장하면 끝. 필요한 날 아침에 만들어 그날 회의에 씁니다. 본사 개발 큐에는 애초에 줄이 생기지 않습니다.

개발 인력의 재배치 SHIFT

반복 화면 개발에서 풀려난 리소스는 데이터 품질·신규 과제로 이동합니다. "개발 부담 감소"의 실제 의미는 인력의 상향 재배치입니다.

가치 ① 심화 - "LLM에게 시키면 되지 않나요?"

02 · Value

맞습니다, LLM도 대시보드 코드를 만들어 줍니다. 하지만 만들 때 한 번과 운영하며 매일 고치는 일은 다른 문제입니다.

관점LLM 코드 생성으로 만들 때aisight Studio로 만들 때
제작 시간프롬프트 → 코드 → 실행 환경 준비 → 디버깅. 시도마다 결과 편차가 큼 위젯 조합으로 수 분 - 데이터 연결·배포·권한이 이미 끝난 상태에서 시작
화면 규격만들 때마다 생김새가 다름 - 담당자마다, 세션마다 제각각 모든 대시보드가 같은 규격·디자인 시스템 - 누가 만들어도 GBC 표준 화면
세부 수정"여백만 조금 줄여줘"를 말로 반복 - 다시 생성될 때마다 엉뚱한 곳이 바뀌는 리스크 해당 위젯만 클릭해 직접 미세 조정 - 나머지는 그대로, 결과가 예측 가능
데이터 연결코드마다 DB 연결·권한·보안을 다시 만들고 다시 검증 검증된 연결과 권한 체계 위에서 - 지표 사전과 자동 연동, 숫자가 항상 같음
유지보수생성된 코드 덩어리 하나하나가 관리 대상 - 쌓일수록 부채 저장되는 것은 위젯 설정뿐 - 플랫폼 업그레이드가 전체 화면에 한 번에 적용
LLM은 aisight 안에서 제자리에 씁니다 - 코드 생성이 아니라 질의 · 요약 · 리포트 초안에.

가치 ② 심화 - 쓰던 개인 AI에서 그대로 이어집니다

02 · Value

분석은 대시보드에서 끝나지 않습니다. aisight는 MCP(모델 연결 표준)로 열려 있어, 담당자가 쓰던 개인 Claude·사내 AI에서 지금 보던 화면을 이어받아 분석합니다.

"Claude로 분석" 버튼 ONE CLICK

대시보드 상단 버튼 하나로, 지금 보던 화면의 필터·기간·지표가 질문에 미리 담긴 채 개인 Claude가 열립니다. 복사·붙여넣기 없이 보던 분석을 그대로 이어갑니다. 화면 안에서 바로 여는 채팅 패널도 함께 제공합니다.

MCP 표준 연동 OPEN

aisight가 MCP 서버를 기본 제공합니다. Claude Desktop 등 MCP를 지원하는 AI라면 무엇이든 aisight의 지표·데이터를 직접 조회하며 대화합니다 - 특정 AI에 묶이지 않습니다.

통제는 그대로 GOVERNED

개인 AI로 이어가도 조회는 본인 권한 범위 안이고, 질의는 감사 로그에 남습니다. 밖으로 열리되, 통제는 플랫폼 안에 있습니다.

가치 ③ 거버넌스 - 자유와 통제를 동시에

02 · Value

셀프서비스의 그늘은 지표 난립입니다. "같은 이름, 다른 숫자"를 겪어 본 조직일수록 통제 설계가 먼저입니다.

통제 01DICTIONARY

표준 지표 사전

지표의 정의·산식·데이터 출처를 플랫폼에 한 번 등록하면, 누가 만든 대시보드든 같은 정의를 씁니다. "eStore 전환율"이 법인마다 다르게 계산되는 일이 구조적으로 사라집니다.

예시

"eStore 전환율 = eStore Revenue 주문 / Clicks" - 산식이 위젯에 자동 표기

지표 정의의 단일 출처(Single Source).
통제 02ACCESS

권한과 행 수준 보안

역할·조직 기준으로 화면 접근을 통제하고, 데이터는 행 단위로 필터링합니다. 유럽 담당자는 유럽 데이터만, 경영진은 전체를 - 같은 대시보드에서.

예시
